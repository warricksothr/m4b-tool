# Test Fixtures & Equivalence Testing

This document describes the fixture inventory the Go port needs and how
to establish functional equivalence with the PHP tool.

## Principle

We don't compare output files byte-for-byte (see
[README.md](README.md#fidelity-target)). Equivalence is measured on
**observable properties**:

- Duration (± some small epsilon, ≤ 100 ms for transcoded outputs).
- Chapter count, start times (± 1 second), and titles.
- Required tag presence and string equality (title, artist, album,
  albumArtist, year, track, disk, genre, description, encoder).
- Cover art presence and pixel dimensions (not hash — codecs differ).
- Audio stream codec and channel count.

## Fixture categories

### 1. Source audio

| Fixture                          | Purpose                          | How to obtain                                   |
|----------------------------------|----------------------------------|-------------------------------------------------|
| `short-mp3-silence.mp3`          | 30 s, synthetic speech + 2 silences | Generated with ffmpeg `anoisesrc`/`sine` + gaps |
| `five-mp3s/`                     | 5× 10 s mp3s for merge           | Same generator, different pitches               |
| `one-m4b-no-chapters.m4b`        | baseline for `chapters` command  | ffmpeg-encoded from a single mp3                |
| `one-m4b-with-chapters.m4b`      | baseline for `split` command     | Generated by PHP `merge` on `five-mp3s/`        |
| `one-flac-plus-cue/`             | flac + cue sheet                 | Ripped/generated pair                           |
| `mixed-bitrate/`                 | mp3s with different bitrates     | Re-encode `five-mp3s/` at 96/128/192            |
| `with-cover/`                    | mp3 with embedded JPEG cover     | Use ffmpeg `-c:v copy -attach`                  |
| `unicode-metadata/`              | files with non-ASCII title/artist | Regenerate `five-mp3s/` with unicode metadata   |

Keep total fixture size well under 50 MB so they can live in git. Use
short durations; audibility is not the point.

### 2. Chapter source files

| Fixture                          | Purpose                                 |
|----------------------------------|-----------------------------------------|
| `chapters-epub.epub`             | EPUB with TOC covering 5 chapters       |
| `chapters-cuesheet.cue`          | cue sheet with 5 tracks                 |
| `chapters-ffmetadata.txt`        | raw FFMETADATA chapter block            |
| `chapters-mp4chaps.chapters.txt` | mp4chaps-format text file               |

### 3. Expected outputs

For each `(command, fixture set, flags)` triple, record a sidecar
`expected.json`:

```json
{
  "duration_ms": 50000,
  "chapters": [
    {"start_ms": 0,     "title": "Chapter 1"},
    {"start_ms": 10000, "title": "Chapter 2"}
  ],
  "tags": {
    "title": "Test Book",
    "artist": "Test Author",
    "album": "Test Book",
    "genre": "Audiobook"
  },
  "has_cover": true,
  "cover_dimensions": [600, 600],
  "audio_codec": "aac",
  "channels": 2
}
```

The Go test suite probes the produced output (via the same `ffmpeg` /
`mp4info` wrappers the app uses) and compares to the sidecar.

## Capture workflow

One-time script to generate the `expected.json` set from the PHP tool:

```bash
# Pseudocode — actual script lives in testdata/gen-expected.sh
for fixture in testdata/cases/*/; do
    php-m4b-tool $(cat "$fixture/cmd.txt") -o "$fixture/out.m4b"
    probe "$fixture/out.m4b" > "$fixture/expected.json"
done
```

Run once against a known-good PHP build. Commit the `expected.json`
files. Discard the `.m4b` outputs — they're large and we're not
comparing binaries.

## Test tiers

**Tier 1 — unit.** Pure-Go tests for chapter algorithms
(silence parsing, shifting, grouping), tag mapping, cue parser, EPUB
TOC extractor. No subprocess. Fast. Run on every commit.

**Tier 2 — integration.** Fixture-based end-to-end tests that invoke
the built binary on each fixture set. Require ffmpeg + mp4v2 on PATH.
Run in CI on a container with those tools, and gated behind a build
tag `integration` locally.

**Tier 3 — parity.** Optional, not gating CI. A test that runs both
the PHP tool and the Go tool on the same fixture and diffs the probed
properties. Used during porting, turned off once parity is established.

## Fixture hygiene

- No copyrighted audio. Generate everything with ffmpeg or use
  public-domain sources (e.g. LibriVox clips truncated to 10 s).
- Deterministic generation: commit the generator script too so anyone
  can regenerate.
- Small: aim for < 100 KB per audio fixture.
